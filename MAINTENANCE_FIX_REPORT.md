# Maintenance Report Creation - Fix Report

**Date:** August 24, 2026  
**Status:** ✅ FIXED  
**Error:** "Failed to submit maintenance report: Failed to create maintenance report"

---

## ROOT CAUSE IDENTIFIED

**Issue:** RLS (Row Level Security) policy on `maintenance_reports` table was too restrictive.

### Specific Problem:

The `employee_create_maintenance_reports` RLS policy only allowed **EMPLOYEE** and **INSTITUTION_MANAGER** roles to INSERT maintenance reports, but **NOT ICT_STAFF**.

**Original Policy (Line 244-249 in 002_create_rls_policies.sql):**
```sql
CREATE POLICY "employee_create_maintenance_reports" ON maintenance_reports
  FOR INSERT
  WITH CHECK (
    public.current_user_role() IN ('EMPLOYEE', 'INSTITUTION_MANAGER') 
    AND institution_id = public.current_user_institution()
  );
```

### Why This Caused Failure:

Even though the backend uses **service role key** (which should bypass RLS), the RLS `WITH CHECK` clause was still being evaluated in certain scenarios, causing inserts to fail when:

1. The JWT context wasn't properly set (service role doesn't set JWT claims)
2. The `current_user_role()` function returned NULL
3. The policy check failed, blocking the INSERT

### 2. RLS Policy (Main Fix)

**File:** `backend/database/migrations/002_create_rls_policies.sql`

**Lines Changed: 244-249**

**Before:**
```sql
CREATE POLICY "employee_create_maintenance_reports" ON maintenance_reports
  FOR INSERT
  WITH CHECK (
    public.current_user_role() IN ('EMPLOYEE', 'INSTITUTION_MANAGER') 
    AND institution_id = public.current_user_institution()
  );
```

**After:**
```sql
CREATE POLICY "employee_create_maintenance_reports" ON maintenance_reports
  FOR INSERT
  WITH CHECK (
    public.current_user_role() IN ('EMPLOYEE', 'INSTITUTION_MANAGER', 'ICT_STAFF') 
    AND institution_id = public.current_user_institution()
  );
```

**Change:** Added `'ICT_STAFF'` to the allowed roles list.
